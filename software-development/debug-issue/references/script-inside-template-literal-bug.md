# `<script>` Inside JS Template Literal: HTML Parser Bug

## Symptom

A single-page HTML dashboard (`.html` file with inline `<script>` tags) fails to execute *any* JavaScript. The page loads but shows static HTML only — no dynamic content, no console errors other than a generic "exception". All `typeof` checks on functions defined in the script return `undefined`.

## Root Cause

When a `<script>` tag appears **inside a JavaScript template literal** (backtick string) that is itself inside an outer `<script>` tag, the browser's HTML parser interprets the `</script>` as closing the *outer* script element:

```html
<script>
  function renderSomething() {
    return `
      <div>
        <script>
          // This </script> closes the outer <script> tag!
        </script>
      </div>
    `;
  }
</script>
```

The HTML parser sees `</script>` and closes the outer `<script>` tag immediately, regardless of nesting context. Everything after that point — including the rest of the function, all subsequent functions, and the `setView('ratings')` init call — is treated as raw HTML text and never executes.

## Why It Happens

The HTML spec says the parser looks for the **literal string** `</script>` (case-insensitive) in the text content of a `<script>` element. Template literals are just text at parse time — the JS engine hasn't run yet, so the backtick delimiters mean nothing to the HTML parser.

This affects:
- Inline scripts in `.html` files
- Template literals that generate HTML containing script tags
- Any `</script>` text inside a JS string within an inline `<script>`

## Fix Options

### Option A: Split the string (recommended for dynamic injection)

When the script tag will be injected via `innerHTML`:

```javascript
`...<scr` + `ipt>...<\/scr` + `ipt>...`
```

But **scripts injected via innerHTML don't execute anyway**, so...

### Option B: Event delegation instead of inline scripts

If you're generating HTML with chart tooltips or other interactive behavior, never put `<script>` in the template. Use event delegation on a parent container that exists at page load:

```javascript
// Instead of inline script in the template:
document.getElementById('content').addEventListener('mouseover', function(e) {
  const dot = e.target.closest('.chart-dot');
  if (!dot) { /* hide tooltip */ return; }
  /* position and show tooltip */
});
```

### Option C: External `.js` file

Move the template-rendering code to an external JS file (loaded via `<script src="...">`). External files don't have this parser issue because they're loaded as pure JS.

## Diagnosis Checklist

- [ ] Check if the page has a single inline `<script>` tag that spans the whole JS
- [ ] Search for `</script>` inside template literals (backtick strings)
- [ ] Check if `typeof setView === 'undefined'` or other defined functions
- [ ] Check for `</script>` anywhere in JS string content inside `<script>...</script>`

## Prevention

- Never put `<script>` tags inside JS template literals in inline scripts
- For tooltips, hovers, or other interactive overlays generated by templates, add delegated event listeners in the main script body instead of injecting inline scripts
- If you must inject interactive behavior dynamically, use MutationObserver or attach event listeners after `innerHTML` assignment
